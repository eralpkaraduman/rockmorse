# Rockmorse (C port)

A C rewrite of Rockmorse, the Ludum Dare 30 game by Super Damage, at the post-compo commit `19ad7cb` of https://github.com/superdamage/LD30.
It is plain C17 on raylib 6.0 and Box2D v3.1.1. CMake downloads both on the first configure, checks them against pinned SHA-256 hashes, and links them statically. Every build is self-contained.

Walk with the arrows or WASD. Hold Space near a rock to pull it. Hold M to see the whole answer. H shows the help.

## Layout

- `src/unity.c`, `src/unity.h`: the engine layer. It covers only the Unity features the scripts use: the frame loop, time, input, transforms, sprites, sprite animation, the camera, GUIText, TextMesh, GUITexture, audio sources and scene switching.
- `src/physics.c`, `src/physics.h`: Unity 2D physics on Box2D 3. Trigger and collision events count per collider pair and reach both owners.
- One C file per Unity script, named after it. `level_loader.c` is `LevelLoader.cs`, `rover.c` holds `Rover`, `RoverInsideTrigger` and `VisibleOnTrigger`, and so on. `game.c` runs the Game scene in a fixed order. `main.c` opens the window.
- `src/values.h`, `src/tables.h`, `src/asset_tables.h`, `src/code_constants.h`: generated by `tools/extract.py`. Never edit them by hand.
- `tests/check.c`: logic checks that run without a window.
- `assets/`: the sprites, sounds and font the game uses, copied from the Unity project or, for some sounds, from the 2016 build.
- `web/site-content.html`: this game's text for the GitHub Pages cover page.
- `web/assets/`: QOA copies of the sounds, which the web build ships instead of the WAV files.
- `screenshots/`, `rockmorse-cover-630x500.png`, `ITCH.txt`: the cover page and itch.io images and text.

## Build

Desktop (macOS, Windows, Linux) needs CMake 3.24 or newer, a C17 compiler, and network access on the first configure.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
./build/rockmorse
```

On Linux, install the X11 and OpenGL headers first.
On Debian or Ubuntu that is `libx11-dev libxrandr-dev libxinerama-dev libxcursor-dev libxi-dev libgl1-mesa-dev`.

Web needs Emscripten. With Homebrew's Emscripten on macOS, set `EMSDK_PYTHON` to a Python 3.12 if the default Python is newer.

```sh
emcmake cmake -S . -B build-web -DCMAKE_BUILD_TYPE=Release
cmake --build build-web
python3 -m http.server 8765 --bind 127.0.0.1 --directory build-web
```

Then open http://127.0.0.1:8765/.

## Checks

Logic checks run from this folder:

```sh
./build/rockmorse_check
```

They cover Morse encoding and placeholder layout, the sol clock and decode timing, axis smoothing, both pause paths, the 0.6 s placeholder clearing, life support running out, the physics bridge and the rover screen text with its kept wrapping bug.

Every original code comment must be in the C code, marked `// original:`. This check confirms it. It skips `CameraFollowBounds.cs`, which no scene uses and the port leaves out.

```sh
python3 -I ../tools/check_comments.py ../extract/source_comments.json src
```

Static analysis reads the code without running it. Run it after a desktop configure, which downloads the headers into `build/`.

```sh
cppcheck --enable=warning,performance,portability,style --std=c11 \
    -D__STDC__=1 -D__STDC_VERSION__=201710L --quiet --inline-suppr \
    -I src -I build/_deps/raylib-src/src -I build/_deps/raylib-src/src/external \
    -I build/_deps/box2d-src/include --suppress=missingIncludeSystem "--suppress=*:build/_deps/*" src tests
for f in src/*.c tests/*.c; do clang --analyze -std=c17 -I src -I build/_deps/raylib-src/src \
    -I build/_deps/raylib-src/src/external -I build/_deps/box2d-src/include "$f" -o /dev/null; done
```

The clang analyzer reports one dead store inside raylib's copy of `stb_truetype.h`, which `unity.c` includes. That is third-party code.

AddressSanitizer catches bad memory access, and UndefinedBehaviorSanitizer catches undefined behaviour. Both run the logic checks with extra checking compiled in.

```sh
cmake -S . -B build-asan -DCMAKE_BUILD_TYPE=Debug \
    -DCMAKE_C_FLAGS="-fsanitize=address,undefined -fno-omit-frame-pointer -fno-sanitize-recover=undefined" \
    -DCMAKE_EXE_LINKER_FLAGS="-fsanitize=address,undefined"
cmake --build build-asan --target rockmorse_check
./build-asan/rockmorse_check
```

On macOS, the built-in `leaks` tool finds memory that was never freed. Run it on the Release check, not the sanitizer build. On Linux, AddressSanitizer reports leaks itself.

```sh
leaks --atExit -- ./build/rockmorse_check
```

## How the data was extracted

The game's numbers, text and assets come from the original project, never from guesses. `tools/extract.py` reads the Unity project and the 2016 Mac build with UnityPy, once, on a dev machine. Its output is committed. The game build never runs it.

It writes these:

- `extract/`: every scene, prefab, clip, material and setting as JSON, with references written as asset paths. It also holds facts from the 2016 build, the polygon pieces and every original code comment.
- `port/src/values.h`: one constant per row of the value table in `build_values()`. Each row names a C constant and its source in the dumps, and the constant's comment repeats that source.
- `port/src/tables.h`: the 8 messages and the Morse table.
- `port/src/asset_tables.h`: sprites, sounds, the font and the animation clips.
- `port/src/code_constants.h`: strings and numbers that live only in the C# code, each checked against its source line.
- `port/assets/`: only the files the game uses.

Unity's concave colliders are split into convex pieces of at most 8 points, as Box2D 3 needs. The script checks every piece against Box2D's rules, and `tests/check.c` runs `b2ComputeHull` on each.

In step 10 of the port, the table lost every row that no C code read. To use another value, add its row back to `build_values()` and rerun the script.

To rerun it, you need the LD30 repo and a Python 3.12 venv with UnityPy 1.25.4 (`tools/requirements.txt`). From the repo root:

```sh
python3.12 -m venv tools/.venv
tools/.venv/bin/pip install -r tools/requirements.txt
tools/.venv/bin/python -I tools/extract.py <LD30>/Unity/LD48-Unity \
    <LD30>/Unity/Bin/Mac/RockMorse.app/Contents/Resources/Data
```

The output is deterministic. A rerun on unchanged input changes no file. Its asserts check the facts the port relies on, so a changed input fails loudly. Do not run it with `-O`.

## Web page and touch controls

On a touch screen, a control bar sits under the game: a D-pad, Pull (Space), Map (M) and Help (H). Pull and Map work while held, like the keys. A tap on the game is a mouse click, for the title's buttons and the screens a click skips. The page never zooms or scrolls. With a keyboard, the bar stays hidden. Add `?touch=1` to the address to test the touch layout on a desktop.

The bar calls `flx_touch_key()` in `src/unity.c`, which feeds the same key state as the keyboard. A gamepad feeds it too, through `gamepad_poll()`. The D-pad is the arrows, A is Space, the left shoulder is Tab and Start is H. The left stick stays analog, as in the original.

The web page and the touch controls are shared with Kurban Bayrami, which keeps them in its `port/web/`. On every configure, CMake downloads `shell.html.in`, `site.html.in`, `touch-controls.js` and `touch-controls.css` from that repo's `main` branch. It fills in this game's title, tagline, colours, game shape and touch keys. `WEB_TOUCH_TAP_CLICKS ON` turns on the taps as clicks. The cover page's text comes from `web/site-content.html`.

A change pushed to Kurban reaches this game on its next configure. GitHub may take up to 5 minutes to serve the new files. For a build that must not change, pin a Kurban commit. To try changes to the shared files before they are pushed, copy them from a local checkout instead:

```sh
emcmake cmake -S . -B build-web -DCMAKE_BUILD_TYPE=Release -DSHARED_WEB_REF=<commit hash>
emcmake cmake -S . -B build-web -DCMAKE_BUILD_TYPE=Release -DSHARED_WEB_DIR=<kurban-bayrami>/port/web
```

The page shows a loading bar until the game starts. The mouse wheel over the game scrolls the cover page.

### Sounds on the web

The WAV files are 27 MB of the game's 28 MB. The 115 s ambience loop alone is 22 MB. So the web build ships QOA copies from `web/assets/` instead, and the download is 6 MB. QOA is a simple lossy format that raylib reads. It keeps every sound's exact length, so the loops stay gapless. The desktop build keeps the WAV files.

`tools/wav_to_qoa.c` makes the copies. The desktop build compiles it. After the WAV files change, run it from this folder:

```sh
./build/wav_to_qoa assets web/assets
```

## Publish on itch.io

```sh
emcmake cmake -S . -B build-web -DCMAKE_BUILD_TYPE=Release
cmake --build build-web --target itch
```

Upload `build-web/rockmorse-itch.zip`. On the itch.io project page, use these settings:

- Kind of project: HTML.
- Tick "This file will be played in the browser".
- Viewport dimensions: 660 x 440.
- Tick "Fullscreen button".
- Tick "Mobile friendly", with Portrait if an orientation setting appears.

`ITCH.txt` has the page text and the rest of the settings.

## Publish on GitHub Pages

The site goes to https://eralpkaraduman.github.io/rockmorse/. It has a cover page at the root, from `web/site.html`, and the game itself under `play/`.

```sh
emcmake cmake -S . -B build-web -DCMAKE_BUILD_TYPE=Release
cmake --build build-web --target pages
```

This assembles the whole site in `build-web/pages/`: the cover page, `cover.png`, `screenshots/`, the Joystix font as `fonts/system.ttf` for the page heading, and the game in `play/`. Commit that folder's contents to the `gh-pages` branch and push it. GitHub serves that branch.

## Faithfulness notes

The port follows the 2016 builds. Where the data could not say how Unity behaved, the port measured the 2016 WebGL build in headless Chrome. `INVENTORY.md` section 11 lists every result. The main ones:

- Update runs at 60 Hz, as the WebGL build did in a browser. Fixed updates and physics run at 50 Hz. Several effects ease by a fixed fraction per frame, so the rate matters.
- Walking speed, the map zoom curve, rock coasting, rock spin and the speed while pulling match measurements.
- The sol length, message timing, rover screen text, death time and text layout match.
- The rock shatter follows rules measured frame by frame (`src/effects.c`).
- The strain sound never plays, because its AudioSource is disabled. The 2016 build logs "Can not play a disabled audio source" there too.

### 3D audio

The WebGL build was measured with hooks on its WebAudio calls (`src/unity.c`, audio section):

- Volume is AudioSource.volume times the rolloff. Distances are 3D, so z counts. Logarithmic is min / distance, flat past the max distance. Linear runs from 1 at the min distance to 0 at the max. Custom curves are read at distance / maxDistance. Every logged value matched to 4 or 5 digits.
- Pan uses the listener's orientation, including the kept flip: the listener faces the other way to the player. WebGL pans with Chrome's HRTF model. raylib cannot do that, so the port uses WebAudio's equal-power law for the same azimuth.
- Doppler is on in the build. The pitch follows the frame-to-frame velocity of the listener and the source, up to about 3% while walking. It drops back to exactly 1 on frames with no physics step.
- Spread has no WebGL counterpart, so the port leaves it out.

How FMOD in the Mac build pans, spreads and applies Doppler was not verified. The measured speed of sound was about 340, with noise. The port uses `AUDIO_SPEED_OF_SOUND`, 347, from the project settings.

### Reverb

The Game scene has two AudioReverbZones, `Rover/Reverb` and `RocketPrefab/Reverb`. Both use Unity's preset 22, "Sewer pipe". The 2016 Mac player holds the same preset table, and its values match the ones the scene stores.

`src/unity.c` runs a small reverb on raylib's whole mix, built from those values:

- Room sets the level of all reflected sound. Room HF makes it 10 dB quieter at 5 kHz.
- The early reflections start 14 ms after the sound. The late part starts 21 ms after them.
- The late part fades by 60 dB in 2.81 s. At 5 kHz it fades 0.14 times as fast.
- The reverb is at full strength within 1.3 units of a zone, and gone at 2 units. The player is that close only inside the rover or the lander.

`tests/check.c` measures the first reflection, the decay time and the level on a test click.

Some limits remain:

- The 2016 WebGL build has no reverb. Its audio code never creates a ConvolverNode or other effect node. The port plays the reverb on the web as well, as the Mac build does.
- Nobody could listen to the Mac build here. So the port follows the zone's numbers, but its sound may differ from FMOD's.
- Unity sends only the 3D sources to the reverb. The port's reverb takes the whole mix. So the 2D start jingle and slot beep also get it while the player stands in a zone.
- The zone's density setting is left out.

### Known small differences

- The 2016 build runs one physics step in the Game scene's first frame, before the tutorial pauses it. Rocks that start in the rover's repeller shatter there, and their sound plays under the tutorial. The port's first frame may not run a step, so these sounds can come at the first step after Space instead. The effects look the same, because they wait during the pause in both.
- The overlap order of rocks at the same z is the port's slot order. The 2016 build's order was not measured.
- Whether Unity 5.4 sends an exit event when a rock is destroyed inside a placeholder was not measured. The port sends one.
